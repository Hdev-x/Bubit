# 데이터 저장과 삭제 안내

이 문서는 현재 공개 소스를 **로컬에서 실행할 때의 구현**을 설명합니다. 외부 서비스의 개인정보 처리방침을 대신하지 않습니다. 외부 서비스는 아직 배포되지 않았으며 운영 주체·보존 기간·문의처 등은 공개 운영 전에 확정해야 합니다.

## 서버에 저장하는 정보

실행자가 설정한 PostgreSQL을 사용합니다. 테이블 정의는 [schema.sql](schema.sql)에 있습니다.

| 정보 | 저장 내용과 사용 |
| --- | --- |
| 회원 | 이메일(로그인 ID), 닉네임, BCrypt 비밀번호 해시, 역할·계정 상태. 가입·인증과 접근 제어에 사용합니다. |
| 거래소 연결 | 회원 ID, 거래소·조회 대상·라벨·활성 여부·생성/수정 시각, 암호화된 API key·secret·passphrase. 선택한 Bitget 계좌 조회에 사용합니다. |
| 수동 평균단가 | 회원 ID, 거래소·코인·입력한 평균단가·생성/수정 시각. 현물 계좌 화면의 원가 표시에 사용합니다. |

비밀번호는 해시로 저장합니다. 거래소 자격증명은 서버의 설정 키를 사용하는 AES-256-GCM으로 암호화해 저장하고, 조회 요청을 보낼 때 서버에서 복호화합니다. API key 목록 응답에서는 키 일부만 표시하고 secret·passphrase는 반환하지 않습니다. 암호화 설정 키와 DB 접근 권한은 실행 환경에서 별도로 보호해야 합니다.

## 브라우저에 저장하는 정보

- 로그인 JWT를 `localStorage`에 저장하고 로그아웃 또는 인증 실패 처리 시 제거합니다.
- 관심종목, 시장별 드로잉, 차트·지표 설정, 통화·잔액 숨김, 탭 순서·창 배치 등 화면 설정을 `localStorage`에 저장합니다.
- 차트 테마는 `localStorage` 외에 365일 만료의 `SameSite=Lax` 쿠키에도 저장합니다.

이 설정들은 브라우저·사이트 저장소 단위입니다. 로그아웃해도 화면 설정과 드로잉은 남으며, 같은 브라우저를 공유하면 다음 사용자가 볼 수 있습니다.

## 외부 요청과 로그

회원가입·로그인 정보와 등록한 거래소 자격증명은 연결한 Bubit API로 전송됩니다. Bitget 계좌 조회 시 서버는 API key·passphrase와 서명을 Bitget으로 보냅니다. Secret은 서명을 만드는 데 사용하며 그 값 자체를 요청 헤더로 보내지는 않습니다.

공개 시세·차트는 서버 또는 브라우저에서 Binance·Bitget·Upbit·Bithumb·CoinGecko를 호출합니다. 환율은 `open.er-api.com`, 코인 이미지는 CoinGecko·GitHub raw·jsDelivr에서도 불러옵니다. 브라우저가 직접 호출하면 해당 제공자에 브라우저의 IP 등 연결 정보와 요청 경로가 전달되고, 서버 경유 요청에서는 서버가 외부 연결을 수행합니다.

API key 저장·활성화·삭제 같은 서버 로그에는 회원 식별자(이메일), 거래소·조회 대상·키 ID가 포함될 수 있습니다. 오류 로그에는 예외 정보가 남습니다. 공개 Issue에 로그를 첨부할 때 이 정보와 자격증명을 제거하세요. 로그 보존 기간·접근 권한·백업은 실행 환경에서 관리하며 코드에 일괄 보존 정책은 정의되어 있지 않습니다.

## 삭제할 수 있는 범위

| 동작 | 지워지는 정보 |
| --- | --- |
| 로그아웃 | 현재 브라우저의 로그인 토큰. 서버 계정·연결 키·차트 설정은 남습니다. |
| 연결 API key 삭제 | Bubit DB에 저장한 해당 연결 정보. 거래소 자체의 키를 폐기하는 동작은 아닙니다. |
| 수동 평균단가 삭제 | 해당 코인의 Bubit 수동 원가 기록. 거래소 거래 내역은 바뀌지 않습니다. |
| 브라우저 사이트 데이터 삭제 | 해당 사이트의 토큰·드로잉·관심종목·설정·테마 쿠키. 서버 데이터는 남습니다. |

회원 탈퇴·전체 데이터 내보내기·전체 삭제를 위한 사용자 UI/API는 아직 없습니다. 로컬 서버·DB의 관리자가 보존·백업·삭제를 관리해야 합니다. 운영 서비스에서 필요한 삭제 요청 접수와 보존 기간은 외부 공개 전에 별도로 준비해야 합니다.
