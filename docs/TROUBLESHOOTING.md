# 트러블슈팅

## 늦은 REST 응답이 실시간 봉을 되돌리는 문제

**상황:** REST refresh를 시작한 뒤 WebSocket이 현재 봉을 갱신했는데, refresh 응답이 도착하면서 가격·거래량이 과거 값으로 바뀔 수 있었습니다.

**원인:** REST 응답을 받았다는 사실만으로 최신 상태라고 취급했습니다. 수신 순서와 데이터가 관측된 순서는 다릅니다.

**해결:** refresh 요청마다 WebSocket이 갱신한 봉과 필드를 기록합니다. REST 응답을 합칠 때 해당 OHLC·거래량은 현재 값을 보존하고 나머지 과거 봉은 보정합니다. 시가는 별도 상태에 중복 저장하지 않고 최신 캔들에서 계산합니다.

**검증:** `useCoinCandles.test.tsx`에서 REST 대기 중 WS 갱신, 과거 봉 보정, 현재가·시가 일치를 검증합니다. KRW 거래량 폴링과 refresh의 교차 응답도 검사합니다.

## 종목을 바꿨는데 이전 데이터가 다시 나타나는 문제

**상황:** A→B→A처럼 빠르게 이동하거나 화면을 나간 뒤, 이전 요청 또는 구독 callback이 늦게 실행될 수 있습니다.

**원인:** 종목 이름만 확인하면 처음 A 요청과 나중 A 요청을 구분하지 못합니다. 구독 해제를 호출해도 이미 대기 중인 callback은 실행될 수 있습니다.

**해결:** 거래소·상품·종목·시간봉 식별자에 요청 세대를 함께 사용합니다. 종료된 구독의 callback은 무시하고, 폴링 요청은 timeout·동시 실행 방지·cleanup을 갖춥니다.

**검증:** `useCoinCandles.test.tsx`, `useRealtimePrices.test.tsx` 및 차트 전환 테스트에서 역순 완료, 재시도, 비활성화·unmount를 재현합니다.

## 지표를 꺼도 차트 전환이 느린 문제

**상황:** 기본 캔들이 준비돼도 일봉 같은 보조 응답을 기다리며 화면 표시가 지연됐습니다.

**해결:** 기본 캔들·현재가와 후속 보강 데이터를 분리하고 중복 일봉 요청 및 요청 전 대기를 제거했습니다. 같은 조건으로 이미 진행 중인 요청은 공유합니다. 마켓 상세를 열 때마다 전체 차트를 미리 받는 방식은 사용하지 않습니다.

**검증:** 요청 횟수·진입 대기·실패 후 재시도·종목 식별자 보호를 테스트합니다. 실제 PC·Mobile 전체 체감 속도의 동일 환경 전후 측정은 완료하지 않았으므로 개선율을 제시하지 않습니다.

## CSS를 나누면서 스타일 우선순위가 바뀌는 문제

**상황:** 큰 CSS 파일을 컴포넌트별로 옮기면 선언 내용이 같아도 import·번들 순서가 달라져 배경·배치가 바뀔 수 있습니다.

**해결:** 공용 규칙은 한 곳에서 관리하고 셸 CSS를 컴포넌트보다 먼저 import합니다. 앱별 값 차이는 CSS 변수로 표현합니다.

**검증:** `npm run check:css`가 규칙 순서, 진입점 import, 번들 순서, 주요 최종 선언·media 조건, 두 앱 셸의 클래스 중복을 검사합니다. 빌드 후 실행해야 번들 검사까지 수행합니다.

자동 테스트가 실제 기기의 모든 프레임과 네트워크 단절을 대신하지는 않습니다. PC·Mobile 전환·드로잉·재연결은 실제 환경의 최종 확인 대상으로 남아 있습니다.
